# 책 대조 범위와 출처

제공된 책 사진 11장 183–196쪽(IMG_0841–IMG_0854)과 사용자 메모를 대조했다. 요구사항 → 발행·읽기 분리 → 웹 서버·팬아웃 상세 → 읽기 조립 → 캐시 다섯 영역 → 확장과 운영의 흐름을 따른다. 문장과 그림은 복습을 위한 자체 재구성이다.

기본 요구인 친구 최대 5,000명과 유명인의 대규모 팔로워 확장 사례를 구분했다. 비동기 팬아웃의 지연, 안정 해시와 단일 핫키의 차이, 내구성 기록·재시도, 삭제·권한 재확인, 캐시 복구·커서 페이지네이션은 보충 설명이다. 혼합 모델이 모든 비용을 없애거나 읽기 시점 방식에 핫키가 없다고 단정하지 않았다.

- [TAO: The power of the graph](https://engineering.fb.com/2013/06/25/core-infra/tao-the-power-of-the-graph/): 객체·관계 API와 캐시, MySQL 영속 저장을 함께 설계한 2013년 공개 사례다.
- [TAO 논문 발표 페이지](https://www.usenix.org/conference/atc13/technical-sessions/presentation/bronson): 책에서 연결한 소셜 그래프 저장소 연구 자료다. 현재 서비스 전체의 구조나 본문의 혼합 팬아웃 구현을 입증하는 자료로 확대 해석하지 않는다.
- [Redis의 관측 및 핫키 설명](https://redis.io/docs/latest/operate/rs/monitoring/observability/): 한 키가 한 샤드에 속하는 상황의 부하 집중과 로컬 캐시 대안을 확인했다.
- [stack-diagram](https://stacks.caru.moe/): 기존 장과 같은 그림 구성 방식과 아이콘 표현을 참고했다.
- [10장 알림 시스템](../10-notification/README.md): 아웃박스·결과 미확인·재시도·작업자 증설의 실패 경계를 연결한다.
- [5장 안정 해시](../05-consistent-hashing/README.md): 키 담당 분산과 서버 변경 시 재배치 범위를 연결한다.

읽기 횟수·게시율·평균 배포 대상 수·캐시 항목 수·항목 바이트 수는 계산을 위한 추가 가정이다. 책이 확정한 수치나 제품 실측값이 아니다. 그림은 논리적 역할과 경로를 보여주며 서비스마다 물리 서버 한 대를 배치한다는 뜻은 아니다.
