# 책과 추가 설명의 범위

## 책을 대조한 부분

『가상 면접 사례로 배우는 대규모 시스템 설계 기초 1』 5장 「안정 해시 설계」의 77–88쪽을 확인했다. 서버 수 변경에 따른 나머지 해시의 재배치, 해시 공간과 링, 서버·키 배치, 시계 방향 조회, 추가·제거, 기본 구현의 불균형, 가상 노드와 이동 범위를 본문 순서에 반영했다.

책에 나온 실제 적용 사례로는 Dynamo·Cassandra의 데이터 분할, Discord의 채팅 서버, Akamai의 콘텐츠 분산, Maglev의 부하 분산이 있다. 서로 같은 링 구현이나 같은 복제 정책을 쓴다는 뜻은 아니다. 이 노트에서는 제품 이름을 암기하기보다 구성이 바뀔 때 목적지 변경을 줄이는 원리를 중심으로 설명한다. 제품별 현재 구현을 확인한 목록은 아니다.

## 이해를 위해 재구성한 부분

- 상품 캐시와 0–99 링은 독립적으로 만든 학습 예시다. 책의 서버 번호나 키 좌표를 그대로 재현하지 않았다.
- 추가는 `(이전 점, 새 점]`, 제거는 `(이전 점, 제거 점]`으로 표시했다. 키와 서버 위치가 같으면 그 서버를 선택하는 규칙이다.
- 평균 이동량의 n이 추가 전인지 후인지 구분했다. 본문의 20%는 지정한 구간의 길이로 계산한 값이며, 서버가 네 대일 때의 일반적인 보장값이 아니다.
- 가상 노드의 ‘저장 공간’은 우선 링 위치표의 비용으로 풀었다. 가상 노드와 실제 데이터 복제본을 구분했다.
- 핫 키, 바이트 수와 요청량의 차이, 위치표 조회 비용, 구성 버전과 데이터 이동은 실무적 의미를 보완한 설명이다. 완성된 분산 저장소 구현을 제공하는 것은 아니다.

## 추가 원문

- [Karger 외, Consistent Hashing and Random Trees (1997)](https://people.csail.mit.edu/karger/Papers/web.pdf): 구성 변화에 따른 매핑 변경을 줄이는 원리를 더 살펴볼 수 있는 원 논문이다. 본문의 간단한 링과 원 논문의 전체 캐싱 프로토콜은 구분한다.
- [DeCandia 외, Dynamo (2007)](https://www.allthingsdistributed.com/files/amazon-dynamo-sosp2007.pdf): §4.2는 가상 노드 기반 분할, §4.3은 데이터 복제와 물리 서버를 고려한 복제 대상 선택을 설명한다.
- [stack-diagram](https://stacks.caru.moe/): 기존 장과 맞춘 HTML·이미지 제작 형식을 참고했다. 링은 책의 표현을 참고하여 직접 구성했다.

## 검증 범위

나머지 해시 표, 링 조회와 양 끝의 포함 규칙, 추가·제거 시 전체 100개 위치의 변경 범위, 가상 노드의 물리 서버 연결을 계산으로 확인한다. 본문 그림과 답안 토글의 렌더링도 확인한다. 실제 클러스터의 성능·장애 복구를 측정한 결과는 아니다.
